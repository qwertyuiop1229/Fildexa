## 初回公開の確認結果

2026年11月21日に [Fildexa](https://fildexa.web.app/) を公開した。Hostingのプレビューチャンネルで確認した版を本番に昇格した。

- 既存のNode回帰テスト36件が通過。本番で配信ファイル50点のSHA-256がローカルと一致し、WASMのMIMEタイプを確認した。
- ChromeでサンプルZIPの操作、別ページとの往復、スマホ幅への切替、開発ツールと検証ラボの起動、単体HTMLのJavaScript、Vite構成のTypeScriptフォルダを確認した。
- Chromeのスマホ幅・タッチシミュレーションで、サンプル操作と横方向のはみ出しがないことを確認した。iPad/iPhoneのSafari実機、検証ラボの全機能、外部通信・保存・認証の本番URL上の詳細確認は未実施。

## 既存機能の確認範囲

- 検証ラボには診断、アセット閲覧、2版比較、テスト条件、接続の各タブがある。ファイル閲覧にはPDF、画像、テキスト、表データ、ブラウザ対応の音声・動画、簡易glTF/GLBが含まれる。
- 既存のAPIモックは隔離環境内の対象 `fetch` を扱う。比較は左右の保存領域を分離する。これらは実ブラウザでの詳細な回帰確認も行う。
- 外部通信の初期値はオフ。DNS候補や観測できた通信情報を、実際の接続先IPなどのブラウザ内部情報と区別して表示する。
- 異常系は、破損・暗号化・上限超過のZIP、空ファイル、深いパス、長いファイル名、通信タイムアウト、保存容量超過を優先する。画面側は狭幅・横画面・キーボード・200%ズーム・動きを減らす設定を確認する。

## ビューアー更新と回帰確認

- 単体ファイルとZIP内のファイルで同じビューアーを使用。PDFは前後のページ移動、画像は拡大縮小と背景切替、JSONはキー・値の検索と元のソース表示に対応した。専用ビューアーがないファイルは拡張子と容量、先頭512バイトの16進数・ASCIIを表示する。
- Firebaseの検証URLでPC幅・スマホ幅のChromeを確認。破損PDF、ZIP内の画像とPDF、空オブジェクトのJSON検索、未対応形式を確認した。既存の比較、APIモック、外部通信、プロジェクトごとの保存・復元・削除も検証した。Safari実機と認証の詳細確認は残っている。

## XLSXビューアー

シート選択、セル番地での移動、書式付き日付と数値、保存済みの数式結果、結合セルを実装した。表は行50件・列12件単位で表示する。60,000行のシートで最後の行への移動を確認した。

## DOCXビューアー

見出し・本文・結合セル付きの表を読み取り専用で表示する。目次は長い文書の後半にも移動できる。幅の広い表はスクロール領域に収める。単体とZIP内、250以上の段落・表を含む文書、独自のパーツ構成のStrict DOCXを確認した。

## 残りのファイル形式と接続

- PPTXは元の順番を使い、スライドの切り替え、タイトル・本文・表、基本的な図形と埋め込み画像を表示する。狭い画面や長い本文はテキスト表示に切り替えられる。
- 音声・動画の速度とループ、音声波形、動画フレームのPNG保存、OBJ・STLの形状表示、TAR・TAR.GZ・TGZ・7z、SQLiteの表閲覧・CSV保存を追加した。
- 未対応形式にシグネチャからの形式推定を追加した。日本語のShift_JISのCSVを開き、テキストの編集結果を別ファイルとして保存できる。対応範囲と上限は[ファイルの対応範囲](../../README.md#ファイルの対応範囲)に記録した。
- ローカル互換モードではChromeで別オリジンのIndexedDB、Service Worker、ポップアップ、相対ルートと、Fildexa側のストレージとの分離を確認した。
- ChromeのPC・スマホ幅とWindows版WebKitで形式ビューアーを確認した。Windows版WebKitではWAVを再生できず、コーデック非対応時の案内を確認した。
- 実機でのiPad・iPhone Safari、GoogleアカウントでのOAuth、端末上のPWAインストールは未確認。Googleの検証にはアプリ所有者のテスト用OAuth設定が必要。
